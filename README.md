# F1 Race Strategy Simulator

Computes the optimal pit stop strategy for a given circuit by modeling the
race as a shortest-path problem over the state space `(lap, tire_compound,
tire_age)`, solved with memoized DP.

## Why this is a good interview project
- Real algorithmic core (DP / shortest-path over a DAG), not just CRUD.
- Clean separation: pure algorithm (`simulator.py`) vs. domain data
  (`data.py`) vs. API layer (`main.py`) — easy to explain in an interview.
- Extensible: swap in real telemetry, add safety-car probability, multi-driver
  comparison, etc. without touching the core DP logic.

## Run the DP core directly (no server needed)

```python
from app.simulator import RaceStrategyOptimizer
from app.data import get_circuit, get_compounds

circuit = get_circuit("monza")
compounds = get_compounds("monza")
result = RaceStrategyOptimizer(circuit, compounds).solve()
print(result)
```

## How the algorithm works

State: `(laps_remaining, current_compound, tire_age)`

At each state you choose between:
1. **Stay out** — pay the degraded lap time for the current tire, age it by 1 lap.
2. **Pit** — pay `pit_loss + fresh_lap_time(new_compound)`, reset tire age to 1,
   switch compound (can also "pit" to the same compound for a fresh set).

We recursively compute the minimum total time to finish the race from every
reachable state, memoizing results (`functools`-style memo dict) so each
state is only computed once. This is effectively Dijkstra's algorithm on a
DAG where laps only move forward — no cycles, so plain DP works and runs in
`O(laps × compounds × max_tire_age)` time.

The path is reconstructed backward using the `choice` table to recover the
actual stint sequence (which compound, which laps) that achieves the optimal
total time.

## Extending this project

1. **Real data**: Replace the illustrative numbers in `data.py` with real
   telemetry using the [FastF1](https://github.com/theOehrly/Fast-F1) Python
   library (free, pulls real F1 timing data).
2. **Database**: Add PostgreSQL/SQLite to persist strategies and let users
   query historical simulations instead of recomputing every time.
3. **Safety car / VSC modeling**: Add probabilistic events that change the
   value of pitting on a given lap (turns this into a much richer
   probabilistic DP / expected-value problem — great for showing depth).
4. **Frontend**: A small React page (recharts) showing the stint plan as a
   timeline and comparing 1-stop vs 2-stop vs 3-stop strategies visually.
5. **Multi-driver comparison**: Simulate two drivers with different starting
   tire choices and see who comes out ahead — adds a game-theory flavor.

## Note on the sample data

The lap times, degradation rates, and pit loss numbers in `data.py` are
illustrative approximations inspired by real F1 characteristics — they are
**not** scraped from official telemetry. Swap them for FastF1 data before
treating results as realistic.
